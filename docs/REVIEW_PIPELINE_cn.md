\# CodeSmith 审查流水线



欢迎来到 CodeSmith！我们收到大量社区 PR。为确保审查流程顺畅快速，请先了解以下流水线要求。 



\## 1. CI 门禁（审查前检查清单）

在维护者审查你的 PR 之前，它必须通过我们的持续集成（CI）检查。 



\*\*必需检查（必须通过）：\*\*

请在推送代码前在本地运行这些命令，以避免 CI 失败：

\* \*\*格式化：\*\* `cargo fmt --all -- --check`

\* \*\*Lint：\*\* `cargo clippy --workspace --all-targets --all-features`

\* \*\*测试：\*\* `cargo test --workspace --all-features --locked`



\*\*信息性检查：\*\*

来自 \*\*Greptile\*\* 和 \*\*GitGuardian\*\* 的检查仅供参考。如果它们标记了某些内容，请予以核查，但除非发生密钥泄露，否则它们本身不会严格阻塞审查。



\## 2. 常见失败模式 \& 本地修复

如果 CI 失败，通常是以下三个原因之一：

\* \*\*版本漂移（`Cargo.lock` 过时）：\*\* 在本地运行 `cargo update` 或 `cargo build` 更新 lockfile 并提交更改。

\* \*\*Lint 失败：\*\* 查看上述命令产生的 clippy 警告，并修复被标记的具体行。

\* \*\*Windows 测试抖动：\*\* 偶尔测试可能在 Windows runner 上超时。如果你确信自己的代码没有破坏它，请留言请维护者重新触发 CI。



\## 3. PR 礼仪

为帮助我们快速审查你的代码，请遵守以下事项：

\* \*\*每个 PR 只关注一件事：\*\* 保持 diff 高度聚焦。不要把重构与新功能混在同一个 PR 里。

\* \*\*关联 issue：\*\* 始终在 PR 描述中包含 `Closes #N`（将 N 替换为 issue 编号），以便 GitHub 自动建立关联。

\* \*\*Rebase：\*\* 在请求审查之前，始终把你的分支 rebase 到最新的 `main` 分支上。



\## 4. 审查工作流

CI 通过后，你的 PR 会进入审查队列。

\* \*\*谁来审查：\*\* 核心维护者会审查该 PR。 

\* \*\*`autonomous-ready` 标签：\*\* 如果维护者打上此标签，表示该 PR 在概念上已获批准，并已排队进入我们的自动化集成系统。

\* \*\*夜间循环：\*\* 我们会在夜间运行大规模集成循环。如果你的 PR 获得批准，可能需要等待该夜间循环之后才会最终合并，以确保系统稳定性。



\## 5. 合并后的动作

你的代码合并后，会发生以下自动化动作：

\* `CHANGELOG.md` 会被更新。

\* `npm` 包装器会被同步。

\* 所有平台的二进制重建会被触发。

\* 网站与文档会与你的新更改同步。



感谢你为 CodeSmith 做贡献！
